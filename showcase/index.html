How a packet travels

No agent talks to another directly. Every exchange flows SOURCE → APEX → KNOLL → destination. APEX must call KNOLL.intercept() before routing; a denial drops the packet and writes a tamper-evident audit + a BLOCKED ledger row. DREAM and VISION can never communicate directly, in either direction.

Idle-cheap by construction

Always-on core, ephemeral fleet

Only three roles keep standby presence — the interface, the guard, and the router. DREAM and VISION (and their node matrices) are spun up on demand, claim a slice, run a persona batch, report back through APEX, and self-terminate. You pay for active personas only.

Credibility is the foundation of the moat

Honest by design

The headline number is a conceptual capacity, not a downloadable set of trained weights. We say so plainly — because a claim that survives an engineer's first question is worth more than one that doesn't.

What "~14.3 quadrillion parameters" actually means

It is 20,480 nodes × 100 personas × 7B — a measure of how much addressable persona-capacity the topology can express. It is not 14.3Q trained weights. The honest, economical realization (see the roadmap) is shared base weights + cheap per-persona deltas, and only the active personas ever cost GPU.

Real today — tested

Tamper-evident RoutingPacket · APEX router · KNOLL gate (6 laws + behavioral score) · billing ledger · 20,480-node topology & persona lifecycle · HTTP gateway · Kafka-shaped queue · Prisma/Postgres seam · GPU/7B model seam.

Conceptual — on the roadmap

Real 7B inference on GPU workers · real Kafka & container sandboxes · learned KNOLL · persona specialization & routing · multi-tenancy & marketplace. Each slots behind an interface that already exists.
